Can a local AI agent harness do real work?

Project period · September 2026

A constant-model harness bake-off showed that useful artefacts are not the same as verified completion.

  • Agent Architecture
  • Local AI
  • Evaluation
  • Hermes

In brief

  • We held the local model constant and compared Hermes, DeepSeek Harness and Pi.
  • All could inspect documentation, write scripts and create real files.
  • DeepSeek and Pi both failed a strict finance task by missing required filenames.
  • Pi even declared success after the external verifier had effectively failed.
  • A local agent becomes useful when the harness makes verification part of “done”.

An agent harness wraps a language model with tools, working memory, execution rules and a definition of when work is complete. A fluent answer from the model proves little about that surrounding system. We held the model endpoint constant and asked three harnesses—Hermes Agent, DeepSeek Harness and Pi—to leave behind artefacts which an independent program could accept or reject.

A fairer comparison

Every candidate used the same 32K Qwen-based endpoint. The tasks included an openpyxl exercise which required documentation lookup and a finance data-join task with exact output names and formats. Prompts, workspaces, logs and verifier results were preserved.

DeepSeek Harness and Pi both passed the workbook task. They inspected the local API, wrote durable Python scripts, executed them and produced valid workbooks. Pi took 55 seconds and 14 tool calls; DeepSeek took 133 seconds and 27 calls.

The finance task was more revealing. DeepSeek wrote a reasonable deterministic solution but placed and named the outputs differently from the contract. It then exceeded the 32K context during a compaction attempt. Pi caught and repaired a real join-key bug, produced useful reconciliation files, but also used the wrong output names. Its final message confidently said the job was done.

Under a human glance, both attempts looked productive. Under the unchanged acceptance gate, both failed.

What the harness changes

The model supplied the language and code, but the harness controlled its working memory, edit tools, logs, termination and view of failure. Pi had the clearest JSON event stream and showed genuine incremental repair. DeepSeek’s compressed session log was auditable but less convenient, and its minimal path was context-fragile. Hermes remained the most useful capability per unit of setup, despite its own qualified results.

The experiment also checked OpenClaw-style task execution and later repeated selected work through Hermes with stronger models. Better models improved judgement, but exact filenames and formats still failed. The missing component was not another leaderboard point; it was a gate the model could not wave away.

Result

A local agent can do real work: research an API, write and repair code, execute it and create useful artefacts. It cannot be trusted merely because those artefacts look plausible.

Our next-harness rule became simple: expose the external verifier as a first-class step, allow repair, and forbid a clean final state until it passes. Reliability is an architectural property of the loop, not a personality trait of the model.
