Turning an Astro Slide into a pocket OpenWrt LTE router

Project period · 20–21 November 2026

Droidspaces supplied OpenWrt, Android supplied the radio, and a small ownership-aware VirtualAP change joined them safely.

  • Openwrt
  • Networking
  • Android
  • Wifi

In brief

  • Droidspaces 7.2.0 booted OpenWrt 24.10.7 with NAT, DNS and lifecycle tests passing under SELinux enforcing.
  • OpenWrt’s upstream was pinned to Android’s cellular interface so home Wi-Fi could stay enabled without becoming the WAN.
  • VirtualAP failed when it tried to delete Android’s idle ap0 and create a replacement on the MediaTek driver.
  • A generic patch borrowed only an existing, down, nl80211 AP interface and returned it intact on Stop.
  • An iPhone received an OpenWrt lease, reached the internet over LTE and opened LuCI; repeated saved-profile start/stop cycles preserved Android Wi-Fi.

Start with a disposable container

Once the custom kernel passed Droidspaces’ mandatory checks, we created a deliberately boring OpenWrt smoke test. It used the official OpenWrt 24.10 Minimal AArch64 root filesystem, verified against its published SHA-256, with IPv4 NAT enabled and autostart disabled.

OpenWrt 24.10.7 and procd booted under SELinux enforcing. The container acquired an address, default route and DNS, then reached the internet with zero packet loss.

Stop, clean start and restart all passed.

Even this simple gate caught a harness mistake. Droidspaces reported total: 1, which meant one installed container, while running: [] meant none were running. A classifier initially treated the installed count as live state.

The raw JSON prevented a correct system result from being rewritten to fit a bad assertion.

Keep Wi-Fi and WAN separate

The finished router needed Android Wi-Fi enabled because the MediaTek framework created the AP interface only after its radio stack had initialised. But the router also had to use LTE, not the home Wi-Fi connection, as its upstream.

We pinned the Droidspaces upstream to the observed cellular interface, ccmni0, and disabled IPv6 for this first accepted profile. OpenWrt’s managed LAN used 192.168.42.1/24, with OpenWrt providing DHCP, DNS, firewalling and LuCI.

That left one missing link: hostapd needed a usable AP interface.

The interface that existed but could not be replaced

VirtualAP 3.0.0 normally removes a stale ap0 and asks nl80211 to create a new one. On the Astro, the direct create path failed with -EFAULT when Wi-Fi was off. With Wi-Fi on, Android had already created an idle AP interface.

VirtualAP deleted it, and replacement creation failed with -ENOMEM.

Those errno labels did not mean the handset was out of memory. They described a driver-interface rejection. Android could recreate the interface when its own Wi-Fi framework recovered; VirtualAP could not make an equivalent replacement.

The compatibility strategy was therefore to respect Android’s ownership. The engine now borrows the existing interface only when runtime inspection proves that it exists, is nl80211 type AP and is administratively down. It fails closed for an active interface, the wrong type or an inspection failure.

Borrowing writes an ownership marker. Stop detaches the interface from the bridge, flushes VirtualAP’s addresses, brings it down and leaves it present for Android. Devices without an existing interface retain the original create/delete path.

Host tests covered wrong-type rejection, active-interface rejection, atomic marker creation and release without deletion. The full Linux suite passed, followed by a warning-clean static arm64 build.

The real-client gate

On the Astro, the patched engine borrowed the same ap0 interface, started hostapd on 2.4 GHz with WPA2, and bridged it through vap-br0 to OpenWrt’s vaplan0.

An iPhone joined the test SSID, received a 192.168.42.x lease, browsed the internet over LTE and opened LuCI at 192.168.42.1. Hostapd association, VirtualAP status and OpenWrt’s lease source all recorded one client.

The final acceptance ran two complete saved-profile start/stop cycles, with an extra idempotent Stop in each cycle. The framework-owned AP interface retained the same identity, OpenWrt stopped cleanly, Android Wi-Fi remained healthy and autostart stayed disabled.

Result

The project ended with a manually operated pocket router, not an unattended appliance. It proved the difficult path: rooted Android, ABI-compatible custom kernel, Droidspaces, OpenWrt, a real Wi-Fi client and LTE egress.

The architecture works because each layer keeps the job it is good at. Android retains proprietary hardware support. OpenWrt owns the client network.

VirtualAP provides the narrow bridge between them without pretending it owns Android’s radio interface.

Longer travel soaks, reboot recovery, screen-off behaviour, thermal testing and cellular failover remain separate experiments. The integration repository publishes source patches, reproducible checks and sanitised evidence—not firmware, boot images, credentials or privileged binaries.
