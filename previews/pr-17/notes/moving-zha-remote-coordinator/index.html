Moving ZHA to a remote coordinator

Project period · June 2026

An OpenWRT access point moved the Zigbee radio closer to the garden without moving Home Assistant.

  • Home Assistant
  • Zigbee
  • Openwrt
  • Home Lab

In brief

  • The Zigbee coordinator was poorly placed beside Home Assistant, while an OpenWRT access point already sat nearer the garden.
  • Moving the USB dongle required the correct CP210x kernel driver before a serial device appeared.
  • We removed a stale serial listener and exposed one 115200-baud raw ser2net endpoint.
  • ZHA changed from the old socket address to the new one after backups.
  • Coordinator and mains-powered devices returned after restart; sleepy battery devices were allowed time to report.

In a Zigbee network, the coordinator is the USB radio that forms and manages the mesh. Home Assistant’s ZHA integration normally talks to that radio as a serial device. Here the coordinator—a Sonoff Zigbee 3.0 USB Dongle Plus (ZBDongle-P)—was poorly placed near the automation server, while a Linksys E8450 access point running OpenWRT 24.10.4 already sat nearer the garden. Improving radio placement did not require moving Home Assistant; it required treating the access point’s spare USB port as a remote serial host.

Prepare the remote end

USB enumeration showed the dongle’s Silicon Labs serial interface, but /dev/ttyUSB0 was absent until the CP210x USB-serial package was installed. The access point used ser2net 4.6.2 to bridge that device to the network.

The access point already had ser2net, including a stale static listener aimed at the same device with the wrong speed. We backed up both configuration forms, removed the stale listener and created one raw endpoint mapping the serial device at 115200 8N1. One process now owned the radio.

Move ZHA carefully

Home Assistant’s ZHA entry and the access-point files were backed up before changing the socket target. The subsequent API restart call returned a gateway timeout because Home Assistant dropped the request while restarting; service health, not the HTTP response alone, decided whether the change worked.

The API returned after roughly seven seconds and ZHA reached loaded. The coordinator identified correctly. Mains-powered routers and thermostats came back with link-quality readings. Two battery soil sensors remained unavailable immediately after restart, which was not enough evidence of failure: sleepy devices may wait for their next wake or report cycle.

Result

The coordinator moved closer to the weak end of the mesh without relocating the automation server or passing a USB device into it. OpenWRT became a small serial appliance alongside its network role.

The reusable procedure is short: prove USB enumeration, install the exact serial driver, ensure one listener owns the device, back up both ends, change the socket, restart once and judge recovery by coordinator and device state over time.

The network socket is a live serial link, not an ordinary health-check port. That distinction produced its own later lesson.
