Direct RTSP versus transcoding

Project period · July 2026

Six unnecessary camera transcodes pushed an Unraid host towards 100% CPU and 95°C before the stream graph was simplified.

  • Frigate
  • Cameras
  • Home Lab
  • Reliability

In brief

  • Several cameras were rotated in go2rtc using an FFmpeg H.264 transform.
  • The transformed aliases became the normal detect and record paths.
  • Six continuous libx264 encoders drove the server to roughly 98–100% CPU and 95–97°C.
  • Flipping the cameras in-device allowed normal main and sub streams to return to direct RTSP.
  • Compatibility-only aliases may transcode; always-on recording paths should avoid it unless necessary.

This system used Frigate, an open-source network video recorder running on an Unraid home server. Cameras supplied compressed RTSP feeds; go2rtc routed them to Frigate for detection and recording, with FFmpeg available only when a client needed a different format. Adding cameras did not saturate the gigabit network. Accidentally moving continuous software transcoding into the normal stream path saturated the CPU.

How the cost crept in

Some small cameras were mounted upside down. The quick fix used go2rtc’s FFmpeg source with H.264 video and 180-degree rotation. It worked, and each camera still reported the expected frame rate.

As more cameras adopted the pattern, those generated aliases became Frigate’s normal detection and recording inputs. The server was no longer moving compressed packets between producers and consumers. It was decoding frames, rotating them and running libx264 continuously.

Six such transcodes eventually drove the Unraid host to about 98–100% CPU and temperatures around 95–97°C. Video was functioning, so ordinary camera health looked green while the machine operating it was plainly unhealthy.

Remove work before tuning it

The cameras were flipped in their own firmware. Their normal go2rtc main and sub aliases then returned to direct RTSP URLs. Frigate could consume the compressed streams without a software encode in the middle.

Special _sub_ios aliases remained allowed to use FFmpeg and Opus when client compatibility justified it. They were not the default detect or record path, so their cost existed only when a client requested them.

This distinction is more useful than a blanket “never transcode” rule. Rotation, codec conversion or audio adaptation may be necessary. The mistake is attaching that work to an always-on path without measuring the multiplication: cameras × streams × 24 hours.

Result

Direct RTSP restored the intended architecture: cameras encode once; go2rtc routes; Frigate detects and records. The fix reduced work rather than tweaking encoder threads around a flawed graph.

When a camera system grows hot, draw the media pipeline. A harmless-looking URL prefix can hide a fleet of permanent encoders.
