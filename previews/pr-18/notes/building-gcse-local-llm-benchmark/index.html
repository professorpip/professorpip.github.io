Building a GCSE benchmark for local LLMs

Project period · August–September 2026

How a suspiciously brilliant 84-mark pilot became an auditable 1,019-mark test of local models, vision and exam technique.

  • Local AI
  • Benchmarking
  • Evaluation
  • Ryzen

In brief

  • We built a GCSE-based benchmark to test quantised local models on a stable, mixed workload—not to award pretend grades.
  • A 97.6% pilot was misleading because it selected text-friendly questions.
  • Text-only testing scored 313/361 (86.7%) but covered only 72.5% of available marks; vision raised coverage to 100% with common-question performance unchanged.
  • The frozen expanded baseline scored 893/1,019 (87.6%) across 14 components; Maths, fine visual reading and exam technique exposed the clearest weaknesses.
  • Flash Next led the text-only comparison at 340/361, but speed and agent reliability remained separate deployment decisions.

Short prompts made several local models look clever. We wanted to know whether a quantised model on a 16 GB consumer GPU could sustain useful reasoning across official British GCSE questions.

This is an evaluation benchmark, not a claim that an AI “passed its GCSEs”. Components were partial, some marks subjective, public papers may have appeared in training data, and speaking or practical assessment was absent.

Test platform, August–September 2026: AMD Ryzen 9 3950X, 64 GB system RAM and an NVIDIA GeForce RTX 5060 Ti with 16 GB VRAM. The same local endpoint and frozen question route were used within each controlled comparison; model quant, context and vision/runtime changes were recorded separately rather than treated as interchangeable.

From flattering pilot to useful test

The first Dirk/Qwen3.8 27B run scored 82/84 (97.6%) on selected Maths, Biology and Computer Science questions. It mainly proved the harness. Questions had been chosen because text extraction worked, excluding much of the visual and awkward material. A high score was evidence that the test was too friendly.

We kept the useful method: isolate mark schemes from the answering model, prompt neutrally, freeze raw answers before marking, mark conservatively and retain prompts, decisions and hashes.

The versions

Version Coverage and score What changed
Text only 313/361 (86.7%); 361/498 marks accessible Six AQA components, no tools, calculator, retrieval or answer checking
Native vision 436/498 (87.6%); full coverage Visual questions routed through the model’s vision path
Exam-permitted aids 437/498 (87.8%) Only supplied formula material and allowed calculators
Expanded frozen baseline 893/1,019 (87.6%) 14 subject/component entries with exclusions recorded

The controlled vision comparison mattered most. The same common text questions scored 313/361 in both versions; newly accessible visual questions scored 123/137. Vision expanded access rather than making the model generally cleverer.

Structured diagrams, logic circuits and ordinary graphs worked well. Fine measurements such as burette scales did not. Higher non-calculator Maths, source-specific humanities answers and exam command words exposed other weaknesses. The harness had limits too: PPM images were stable where PNG could crash the vision CLI, and the text server had to release GPU memory before vision loaded.

Permitted aids added only one mark. Presenting the paper properly mattered far more than adding tools.

Comparing local models

The frozen 361-mark text route then compared six profiles:

Model profile Score Practical reading
Flash Next IQ3 340/361 (94.2%) Best academic result; slowest
Qwen3.8 27B IQ4 + MTP 323/361 (89.5%) Strong, faster all-rounder
Dirk/Qwen3.8 27B 313/361 (86.7%) Reference model; stronger broader agent behaviour
Base Qwen3.8 27B 312/361 (86.4%) Nearly identical academic score
Qwen3-Coder 30B 265/361 (73.4%) Fast; coding specialisation did not transfer
Gemma 4 12B 227/361 (62.9%) Long-prompt failures became obvious

Flash Next took about 13.9 minutes and generated near 23 tokens/s; faster 27B profiles were roughly twice that rate. Academic capability therefore became one axis alongside agent reliability, speed and operational complexity in our local AI choices.

Rules worth keeping

  • Freeze raw responses before opening the mark scheme; never rescue and silently re-score an answer.
  • Record every excluded question, mark value and reason.
  • Report capability and coverage separately.
  • Mark subjective answers with visible uncertainty or independent review.
  • Preserve runtime failures and awkward questions as evidence.
  • Do not convert benchmark percentages into theatrical school grades.

The result is a repeatable challenge for the next exciting model. We no longer have to ask whether it feels clever; we can give it the same exam.
