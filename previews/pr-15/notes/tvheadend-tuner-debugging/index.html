TVHeadend tuner debugging

Project period · June–July 2026

Working local streams, two network paths and one noisy USB tuner explained a Plex Live TV failure.

  • Home Lab
  • Tvheadend
  • Plex
  • Raspberry Pi

In brief

  • TVHeadend exposed 110 channels and a local stream probe returned valid transport-stream data.
  • The Raspberry Pi had both wired and wireless addresses, while discovery still advertised an unhelpful path.
  • Plex subscriptions failed quickly and one USB tuner showed uncorrected-block and continuity errors.
  • Disabling only that frontend left the Sony DVB-T HAT serving clean streams.
  • Pinning discovery to wired Ethernet and restarting Plex separated tuner, network and client-state faults.

This installation used TVHeadend 4.3 on a Raspberry Pi 3 Model B Rev 1.2 as a UK Freeview tuner server. A Sony CXD2880 DVB-T/T2 HAT and a PCTV Systems tripleStick 292e USB tuner supplied terrestrial television; TVHeadend’s HDHomeRun emulation exposed those channels to Plex Live TV. Plex could see the guide and channels but would not play them. The tempting diagnosis was “TVHeadend is broken”. Evidence from each layer told a narrower story.

Establish what works

The Pi ran TVHeadend with both the Sony CXD2880 DVB-T/T2 HAT and the PCTV Systems tripleStick 292e. Its API reported 110 channels, 114 services and nine multiplexes. A timed local request for one channel returned HTTP 200, MPEG transport-stream data and about 1.7 MB before the deliberate timeout.

That proved a channel could leave TVHeadend. It did not prove Plex was selecting a healthy tuner or reachable address.

The Pi was dual-homed: Wi-Fi retained its old address while Ethernet became the preferred route. An obsolete proxy container elsewhere was stopped, and TVHeadend’s native HDHomeRun emulation became the intended discovery path.

Follow the failing subscription

TVHeadend logs showed Plex subscribing and unsubscribing after a few seconds. Runtime counters on the USB tuner recorded 116 uncorrected blocks, 30 continuity errors and an error block count of 116. The Sony frontend did not show the same pattern.

After a configuration backup, only the USB DVB-T/T2 frontend was disabled. A 20-second BBC One probe through the Sony succeeded. Plex then showed BBC streams running with TVHeadend subscription errors, uncorrected blocks and continuity errors all at zero.

Discovery was pinned to the Pi’s wired address and the advertised tuner count reduced to one. A remaining “hostname could not be found” message pointed above TVHeadend, towards Plex’s cached DVR state. Restarting the Plex container finally restored playback.

Result

There were at least two faults: a noisy tuner path and stale client/discovery state. Local stream proof prevented both from being conflated with a dead server.

The debugging order is reusable: verify a stream locally, inspect per-subscription and per-frontend counters, remove one suspect input, pin one network path, then reset the consuming client only after the source is clean.
