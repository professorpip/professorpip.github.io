Local SunSynk telemetry without the cloud

Project period · August–September 2026

A Raspberry Pi turned the inverter's RS-485 port into a local Modbus TCP feed for Home Assistant.

  • Home Assistant
  • Energy
  • Modbus
  • Raspberry Pi

In brief

  • The inverter’s cloud integration was useful but not an ideal source for live local control and diagnosis.
  • A small Raspberry Pi connected to the RS-485 port through a USB adapter.
  • A CRC-valid register response proved wiring, speed and unit ID before any service was installed.
  • mbusd exposed the serial bus as Modbus TCP; a Home Assistant add-on read 72 configured sensors.
  • The dashboard kept cloud and local entities visibly separate for comparison.

The starting point was a SunSynk 3.6 kW single-phase low-voltage hybrid inverter with cloud telemetry already visible in the vendor app. We wanted a second, local path whose latency, availability and evidence did not depend on that cloud. A Raspberry Pi 3 Model B Rev 1.2 running Debian 13 became the gateway: a CH340 USB-to-RS-485 adapter reached the inverter, mbusd exposed Modbus TCP, and Home Assistant consumed the readings.

Prove the wire first

The USB RS-485 adapter appeared as a CH340 serial device with a stable by-id path. Passive listens at several common baud rates captured nothing, which did not prove the A/B pair was reversed: Modbus RTU devices often remain silent until addressed.

A read-only request at 9600 8N1, unit 1, asked for holding register zero. The inverter returned a framed value with a valid CRC. That single response established polarity, serial settings and address more convincingly than watching an idle line.

Add a narrow gateway

We built mbusd on the Pi and installed it as a supervised service. It opened the stable serial path and accepted Modbus TCP requests, with retries and conservative RTU spacing. An end-to-end test from another machine repeated the register read over TCP and returned the same value.

Home Assistant’s Sunsynk add-on then pointed at the Pi gateway. Logs identified a single-phase hybrid inverter, the expected 3.6 kW rating and 72 configured sensors. The add-on published local MQTT entities while the existing cloud integration remained intact.

That duplication was deliberate. The dashboard labelled cloud and local sections separately and added read-across charts. Similar names from two sources are dangerous if operators cannot tell which path supplied a value.

Result

The Raspberry Pi became a small protocol boundary: USB and Modbus RTU on one side, ordinary local TCP on the other. Home Assistant no longer needed physical proximity to the inverter, and other read-only tools could test the gateway without opening the serial device directly.

The build order was the main lesson: verify one CRC-good RTU response, verify the TCP bridge, then integrate the application. Layered proof turns “no data” from a wiring mystery into a bounded fault.
