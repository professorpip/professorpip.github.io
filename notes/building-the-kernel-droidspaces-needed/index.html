Building the kernel Droidspaces actually needed

Project period · 20 November 2026

The smallest successful Astro kernel change was not a feature bundle but an ABI-checked namespace fix guided by runtime evidence.

  • Linux
  • Android
  • Kernels
  • Droidspaces

In brief

  • The stock Astro kernel passed every mandatory Droidspaces check except IPC namespaces.
  • Planet’s public source was older than the V07b kernel, so the baseline had to be reconstructed with the shipped toolchain and missing security backports.
  • Enabling POSIX message queues alongside IPC namespaces caused 325 vendor-module CRC mismatches and was rejected before boot.
  • A namespace-only build restored 952 comparable CRC matches, but runtime diagnostics exposed a missing initial namespace pointer.
  • Extending one condition to include CONFIG_IPC_NS made procfs, CLONE_NEWIPC and Droidspaces agree.

One missing requirement

Droidspaces 7.2.0 inspected the rooted Astro and found almost everything it needed. Network namespaces, veth, bridges, TUN/TAP, OverlayFS and the mandatory cgroup features were already available. IPC namespaces were not.

The obvious response was to enable CONFIG_IPC_NS. The risky response was to enable a generic set of “related” IPC options and hope. This phone loads proprietary prebuilt vendor modules, so a kernel can compile, boot and still fail when exported symbol versions no longer match those modules.

We therefore treated ABI evidence as a pre-boot gate.

Reconstructing the baseline

Planet’s visible public Astro source begins with a 2022 commit, while the tested handset ran a May 2023 V07b build. The public build tooling also pointed at an older Android Pie-era compiler, whereas the shipped kernel identified Android clang r383902 and LLD 11.0.1.

Reconstruction combined the phone’s exact running configuration with that toolchain identity, the missing ARM erratum 1188873 and Spectre-BHB backports, and a small MediaTek build correction required by LLD. We then compared kernel symbol CRCs against 1,021 references extracted from the captured vendor modules.

The credible baseline produced 952 matches, zero mismatches and 69 expected references supplied by other vendor modules. That became the control. A new candidate had to preserve those comparable results.

Reject the tempting build

The first minimal-looking candidate enabled POSIX message queues alongside IPC namespaces. It compiled, but the ABI comparison collapsed to 627 matches and 325 mismatches across 220 unique symbols, including module_layout.

That build never deserved to reach the phone. Ignoring modversions or forcing modules would merely hide the incompatibility.

The accepted configuration was narrower:

CONFIG_NAMESPACES=y
CONFIG_IPC_NS=y
CONFIG_PROC_FS=y
# CONFIG_SYSVIPC is not set
# CONFIG_POSIX_MQUEUE is not set

With the necessary namespace-core pieces adapted to the 4.14 tree, all 952 comparable references matched again.

When configuration and runtime disagreed

The namespace-only kernel booted Android cleanly, yet Droidspaces still reported no IPC namespace. A static diagnostic split its combined check into two independent facts:

  • unshare(CLONE_NEWIPC) succeeded in a child process;
  • /proc/self/ns/ipc did not exist.

That contradiction pointed away from syscall support and towards initial namespace registration. In this kernel, init_nsproxy.ipc_ns was populated only when POSIX message queues or SysV IPC were enabled. Our namespace-only configuration could create a new IPC namespace, but procfs had no initial namespace pointer to expose.

The final source change was one extra condition:

#if defined(CONFIG_POSIX_MQUEUE) || defined(CONFIG_SYSVIPC) || \
    defined(CONFIG_IPC_NS)
        .ipc_ns = &init_ipc_ns,
#endif

After rebuilding, the ABI gate remained 952 matches and zero mismatches. /proc/self/ns/ipc existed, unshare(CLONE_NEWIPC) succeeded, and Droidspaces reported both ipc_ns: 1 and requirements_met: 1.

Result

The final image passed two Android/Droidspaces runtime gates and two five-minute hardware soaks separated by a reboot. Display, touch, keyboard, Wi-Fi, cellular, Bluetooth, audio, charging and temperature were manually checked.

No boot image is part of the public integration repository. It contains the source patch, configuration delta and provenance needed to rebuild, while each reader must use the source, ramdisk and boot metadata appropriate to their own firmware.

The reusable lesson is to make the runtime contradiction smaller. “Droidspaces says no” was ambiguous. “The syscall works but the proc link is absent” made a one-line fix discoverable.

What came next

With the kernel gate finally green, an official OpenWrt root filesystem could run under Droidspaces. The final challenge was the Wi-Fi AP interface: Android could create it, while VirtualAP could not replace it. Part three follows that failure to the working LTE router.
